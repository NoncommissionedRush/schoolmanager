# Internationalisation (i18n)

All user-facing text goes through [next-intl](https://next-intl.dev). v1 ships
**British English (`en-GB`)** only — day-month dates, 24-hour clock — but the
app is translation-ready. There is no language switcher yet and URLs carry no
locale prefix.

## Where things live

| Path                         | What                                                               |
| ---------------------------- | ------------------------------------------------------------------ |
| `messages/<locale>/`         | Message catalog, one JSON file per feature namespace               |
| `messages/<locale>/index.ts` | Registers the namespaces of that catalog                           |
| `src/i18n/config.ts`         | Supported `locales`, `defaultLocale`, `defaultTimeZone`            |
| `src/i18n/request.ts`        | Per-request config (locale, messages, time zone, formats)          |
| `src/i18n/formats.ts`        | Named date/time formats (`short`, `long`, `time`, `weekdayShort`…) |
| `src/i18n/next-intl.d.ts`    | Type augmentation — message keys and format names are type-checked |
| `src/lib/i18n/dates.ts`      | Week/weekday helpers for timetables (week start, ranges, times)    |

## Adding a string

1. Pick the feature namespace (`common`, `home`, `timetable`, …). Keys are
   nested by area, e.g. `timetable.empty.week`; reuse the keys in the design
   specs (`docs/design/`) where they are given.
2. Add the key to `messages/en-GB/<namespace>.json`. Use
   [ICU syntax](https://next-intl.dev/docs/usage/messages) for variables and
   plurals: `"lessonCount": "{count, plural, one {# lesson} other {# lessons}}"`.
3. Use it:

   ```tsx
   // Server or shared component
   import { useTranslations } from "next-intl";
   const t = useTranslations("timetable");
   <p>{t("empty.week")}</p>;

   // async Server Component, Server Action, Route Handler, generateMetadata
   import { getTranslations } from "next-intl/server";
   const t = await getTranslations("timetable");
   ```

   Client components get messages from the `NextIntlClientProvider` in the root
   layout. Keys are type-checked — a typo fails `pnpm typecheck`.

New namespace: create `messages/en-GB/<namespace>.json` and add it to
`messages/en-GB/index.ts`.

Never build sentences by concatenating translated fragments; put the whole
sentence in one message with placeholders. Labels for icon-only buttons
(`aria-label`), `alt`, `title` and `placeholder` are user-facing too.

### Lint guard

`pnpm lint` (and CI) fails on hard-coded text in `src/**/*.tsx`: JSX text,
string/template literals rendered as children, and literal values of `alt`,
`title`, `placeholder`, `label` and `aria-*` text attributes. Whitespace and
language-neutral punctuation (`·`, `–`, `/`, …) are allowed.
`src/components/ui/` (shadcn primitives) is exempt — pass labels into those
components as props instead of editing literals into them.

`pnpm test` checks that every catalog has the same keys as the others and that
every message is valid ICU.

## Dates, times and weekdays

- **Instants** (lesson start/end, created at): use the formatter, which applies
  the request's locale and the school's time zone.

  ```tsx
  const format = useFormatter(); // or await getFormatter()
  format.dateTime(lesson.startsAt, "time"); // 09:30
  format.dateTime(lesson.startsAt, "long"); // Wednesday, 14 October 2026
  ```

  Inside messages: `"startsAt": "Starts {time, date, time}"`.

- **Calendar days and weeks** (timetable columns, week navigation): use
  `src/lib/i18n/dates.ts`. Days are `CalendarDate` strings (`"2026-10-14"`),
  so a week never shifts because of the server's or browser's time zone.

  ```ts
  const today = toCalendarDate(new Date(), timeZone); // school's time zone
  const days = weekDates(today, weekStartsOn); // 7 dates, Mon…Sun by default
  formatWeekRange(locale, days[0]); // "12–18 Oct 2026"
  weekdayNames(locale, weekStartsOn, "short"); // ["Mon", …, "Sun"]
  formatTimeRange(locale, start, end, timeZone); // "09:30–11:00"
  ```

  Get `locale` from `useLocale()` / `await getLocale()` and the time zone from
  `useTimeZone()` / `await getTimeZone()`.

- **Week start** is Monday (`DEFAULT_WEEK_START = 1`, `0` = Sunday). Pass a
  school's own setting as `weekStartsOn` once schools can configure it.
- **Time zone**: all times are shown in the school's time zone, never the
  browser's. Until the `School` model stores one, `defaultTimeZone`
  (`Europe/Bratislava`) in `src/i18n/config.ts` is used; then resolve it per
  request in `src/i18n/request.ts`.
- Never hand-build date strings (`${d}.${m}.`) or hard-code weekday names.

## Adding a language

1. Copy `messages/en-GB/` to `messages/<locale>/` (BCP 47 tag, e.g. `sk`, `de`)
   and translate the values — keep the keys.
2. Add the tag to `locales` in `src/i18n/config.ts` and its loader to
   `catalogs` in `src/i18n/messages.ts`.
3. Decide how the locale is chosen and implement it in `src/i18n/request.ts`
   (e.g. a user preference, the school's default, or a cookie; validate with
   `isLocale`). The design spec puts a _Language_ item in the user menu once
   more than one locale exists.
4. `pnpm test` verifies the new catalog has every key and valid ICU messages.
